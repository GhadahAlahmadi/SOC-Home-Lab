# SOC Home Lab – Security Monitoring & Incident Investigation

## Overview

A hands-on SOC home lab built to simulate, detect, and investigate security incidents using Splunk, Sysmon, Windows, Kali Linux, and Ubuntu Server.

The lab focuses on security monitoring, log analysis, IOC identification, event correlation, and incident investigation from a SOC Analyst L1 perspective.

## Lab Architecture

![SOC Home Lab Architecture](home_lab_siem_flow_v2.png)

Kali Linux → Windows 10 → Splunk Universal Forwarder → Ubuntu Server / Splunk Enterprise

### Components

- Kali Linux – Attack Simulation
- Windows 10 – Victim / Monitored Endpoint
- Sysmon – Endpoint Telemetry
- Splunk Universal Forwarder – Log Forwarding
- Ubuntu Server – Splunk Enterprise
- Splunk – SIEM, Detection & Investigation

## Attack Scenarios

### Reconnaissance – Nmap

**Objective:**  
Simulate network reconnaissance against the Windows 10 victim and identify network activity generated by the scan.

**Attack Simulation:**  
Nmap was used from Kali Linux to perform network reconnaissance against the Windows 10 victim in the isolated lab environment.

**Detection & Investigation:**  
The generated network activity was investigated in Splunk using Sysmon Event ID 3.

**Key Indicators:**
- Source IP
- Destination IP
- Destination Port
- Protocol
- Timestamp

**MITRE ATT&CK:**  
T1046 – Network Service Scanning

### Initial Access – RDP Brute Force

**Objective:**  
Detect repeated failed RDP authentication attempts against the Windows 10 victim.

**Attack Simulation:**  
An RDP brute-force attack was simulated from Kali Linux against the Windows 10 victim.

**Detection & Investigation:**  
Windows Security Event ID 4625 was analyzed in Splunk to identify failed authentication attempts and correlate them by source IP and targeted account.

**Key Indicators:**
- Source IP
- Target Account
- Failed Login Attempts
- Logon Type
- Timestamp

**MITRE ATT&CK:**  
T1110 – Brute Force

### Exploitation – Metasploit

**Objective:**  
Investigate endpoint and network activity generated after exploitation of the Windows victim.

**Attack Simulation:**  
Metasploit was used to simulate exploitation against the Windows 10 victim in the isolated lab environment.

**Detection & Investigation:**  
The resulting process creation and network connection activity was investigated in Splunk using Sysmon telemetry.

**Key Indicators:**
- Suspicious Process
- Attacker IP
- Destination Port 4444
- Process Creation
- Network Connection
- Timestamp

**Event Correlation:**

Process Creation → Network Connection → Attacker IP:4444

**MITRE ATT&CK:**  
Technique mapping will be documented based on the observed execution and payload behavior.

### Persistence – Registry Run Key

**Objective:**  
Detect and investigate registry-based persistence on the Windows victim.

**Attack Simulation:**  
A Registry Run Key was configured to automatically execute the payload when the user logs in.

**Detection & Investigation:**  
The registry modification and subsequent process execution were investigated using Windows and Sysmon telemetry in Splunk.

**Key Indicators:**
- Registry Run Key
- Registry Value
- Payload Path
- Process Creation
- Parent Process
- Timestamp

**Event Correlation:**

Registry Modification → Payload Execution → Network Activity

**MITRE ATT&CK:**  
T1547.001 – Registry Run Keys / Startup Folder
